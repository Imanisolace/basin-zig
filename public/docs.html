API Reference

Base URL: https://basin-zig-production.up.railway.app

Authentication

Basin uses two separate auth methods for two separate purposes:

MethodUsed forHow
Bearer <token>Account management — /apikey, /create-payment, /usageYour signed-in browser session token (Clerk)
x-api-key headerThe actual ledger operations — /prove, /verifyThe static key you generate via /apikey
Sign in on the site once, hit /apikey to generate your key, then use that key with x-api-key for every /prove and /verify call from your own backend or scripts.

POST /prove

Builds a Merkle tree over items and returns the root plus a proof for the item at target_index.

Request

{
  "items": ["record-001", "record-002", "record-003"],
  "target_index": 0
}

Response

{
  "root": "0x1a2b3c...  (0x-prefixed, 64 hex chars)",
  "proof": {
    "steps": [
      { "is_right": true,  "has_sibling": true,  "sibling": "8f3c9a...  (64 hex chars, NOT 0x-prefixed)" },
      { "is_right": false, "has_sibling": false, "sibling": null }
    ]
  },
  "target_index": 0
}
A step with "has_sibling": false means that level had an odd number of nodes and this one carried up unchanged — there's nothing to hash it against. sibling is null in that case; don't treat it as an empty string or all-zero value.

Limits

  • Up to 10,000 items per request
  • Combined size of all items in one request: 8MB

POST /verify

Checks whether item is a genuine member of the tree with the given root, using proof.

Request

{
  "item": "record-001",
  "root": "0x1a2b3c...",
  "proof": { "steps": [ ... same shape as returned by /prove ... ] }
}

Response

{ "valid": true }

Limits

  • Item being verified: up to 64KB

POST /apikey

Bearer Creates your API key on first call, or returns your existing one.

curl -X POST https://basin-zig-production.up.railway.app/apikey \
  -H "Authorization: Bearer <session token>"
{ "apiKey": "zk_...", "tier": "free" }

GET /usage

Bearer Current plan, limits, and usage this cycle.

{
  "email": "you@example.com",
  "tier": "free",
  "billing": null,
  "limits": { "prove": 1000, "verify": 5000 },
  "usage": { "prove": 12, "verify": 340 },
  "expires_at": null,
  "apiKey": "zk_..."
}

POST /create-payment

Bearer Body: { "plan": "monthly" | "yearly" }. Returns { "payment_url": "..." } — redirect the user there to pay.

GET /health

No auth required. Returns { "status": "ok" }.

Errors

Non-2xx responses return { "error": "message" }. Common codes: 400 invalid input, 401 missing/invalid auth, 404 item not found, 429 rate or usage limit hit, 500 server error.
